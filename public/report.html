Executive Summary

A comprehensive security assessment was conducted on the Kuros Kubernetes-based student deployment platform. The assessment identified 14 vulnerabilities ranging from Critical to Low severity.

The most severe finding is a Critical SSRF vulnerability that could allow attackers to access AWS EC2 metadata and potentially steal IAM credentials from EKS nodes. Additionally, several resource exhaustion and container isolation issues were identified that could impact platform stability and multi-tenant security.

Immediate remediation is recommended for the Critical and High severity findings to prevent potential credential theft and denial of service attacks.

Critical Findings

vuln-0004 SSRF to AWS IMDS - EKS Node IAM Credential Theft
Critical

Description

Deployed containers can make HTTP requests to the AWS Instance Metadata Service (IMDS) at 169.254.169.254. This allows attackers to retrieve temporary IAM credentials associated with the EKS node role.

Impact

An attacker could steal AWS IAM credentials and use them to access other AWS services, potentially compromising the entire cloud infrastructure. The credentials could be used for lateral movement, data exfiltration, or resource hijacking.

CVSS Score

CVSS 3.1: 9.6 (Critical) - AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H

Proof of Concept

curl http://169.254.169.254/latest/meta-data/iam/security-credentials/
# Returns IAM role name

curl http://169.254.169.254/latest/meta-data/iam/security-credentials/<role-name>
# Returns AccessKeyId, SecretAccessKey, Token

Remediation

1. Enable IMDSv2 with hop limit of 1 on all EKS nodes
2. Implement NetworkPolicies to block egress to 169.254.169.254
3. Use IRSA (IAM Roles for Service Accounts) instead of node roles

High Findings

vuln-0001 Refresh Token Session Hijacking
High

Description

The /api/auth/refresh endpoint accepts refresh tokens without proper validation of the session state. Stolen refresh tokens can be used indefinitely to generate new access tokens.

CVSS Score

CVSS 3.1: 7.4 (High)

Remediation

Implement refresh token rotation and bind tokens to device fingerprints. Invalidate all tokens on password change or logout.

vuln-0005 Missing K8s Resource Limits - DoS via Resource Exhaustion
High

Description

Deployed containers have no CPU or memory limits configured. A malicious user can exhaust node resources, causing denial of service for other tenants on the same node.

CVSS Score

CVSS 3.1: 7.7 (High)

Remediation

Configure LimitRange and ResourceQuota for student namespaces. Set default CPU/memory limits and requests.
